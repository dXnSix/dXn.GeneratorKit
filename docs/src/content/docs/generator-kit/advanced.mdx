# Advanced Topics

This guide covers advanced concepts, performance optimization techniques, and best practices for using Six.GeneratorKit in complex scenarios.

## Performance Optimization

### Memory Management

Six.GeneratorKit is designed with performance in mind, but understanding how to use it efficiently is crucial for large-scale code generation.

#### Use Pooled Builders

Always use `ImmutableArrayBuilder<T>.Rent()` for building collections:

```csharp
// ✅ Good - Uses pooled memory
using var builder = ImmutableArrayBuilder<string>.Rent();
foreach (var item in items)
{
    builder.Add(ProcessItem(item));
}
return builder.ToImmutable();

// ❌ Bad - Creates many intermediate collections
var result = ImmutableArray.CreateBuilder<string>();
foreach (var item in items)
{
    result.Add(ProcessItem(item));
}
return result.ToImmutable();
```

#### Efficient String Building

For large code generation, use proper string building techniques:

```csharp
// ✅ Good - Pre-allocate capacity when known
var sb = new StringBuilder(estimatedSize);

// ✅ Good - Use interpolated strings for simple cases
sb.AppendLine($"public {type} {name} {{ get; set; }}");

// ✅ Good - Use raw strings for complex templates
sb.AppendLine($$"""
    public {{type}} {{name}}
    {
        get => _{{fieldName}};
        set => SetProperty(ref _{{fieldName}}, value);
    }
    """);
```

#### Minimize Allocations in Hot Paths

```csharp
// ✅ Good - Reuse string constants
private const string PublicModifier = "public";
private const string PrivateModifier = "private";

// ✅ Good - Use spans for string operations
ReadOnlySpan<char> nameSpan = memberName.AsSpan();
if (nameSpan.StartsWith("_"))
{

// ✅ Good - Cache commonly used display formats

    SymbolDisplayFormat.FullyQualifiedFormat;
```

### Incremental Generation Optimization

#### Proper Use of EquatableArray

`EquatableArray<T>` is essential for efficient incremental generation:

```csharp
// ✅ Good - Value equality enables incremental caching
public record GeneratorData(
    string Name,
    EquatableArray<PropertyInfo> Properties,  // ✅ Equatable
    EquatableArray<MethodInfo> Methods        // ✅ Equatable
);

// ❌ Bad - Reference equality breaks incremental caching
public record GeneratorData(
    string Name,
    ImmutableArray<PropertyInfo> Properties,  // ❌ Reference equality
    List<MethodInfo> Methods                  // ❌ Mutable and reference equality
);
```

#### Minimize Transform Complexity

Keep transform methods simple and fast:

```csharp
// ✅ Good - Simple, fast transform
private static ClassInfo? GetClassInfo(GeneratorAttributeSyntaxContext context)
{
    if (context.TargetSymbol is not INamedTypeSymbol symbol)
        return null;
        
    return new ClassInfo(
        symbol.Name,
        symbol.GetNamespace(),
        GetSimpleProperties(symbol)
    );
}

// ❌ Bad - Complex analysis in transform
private static ClassInfo? GetClassInfo(GeneratorAttributeSyntaxContext context)
{
    // Expensive operations that should be in Execute phase
    var complexAnalysis = PerformDeepAnalysis(context.TargetSymbol);
    var generatedCode = GeneratePreviewCode(complexAnalysis);
    
    return new ClassInfo(/* ... */);
}
```

## Advanced Patterns

### Multi-Stage Generation

For complex generators, use multiple stages:

```csharp
[Generator]
public class MultiStageGenerator : IIncrementalGenerator
{
    public void Initialize(IncrementalGeneratorInitializationContext context)
    {
        // Stage 1: Collect types
        var types = context.SyntaxProvider
            .ForAttributeWithMetadataName("MyAttribute", ...)
            .Where(static t => t is not null);

        // Stage 2: Group by namespace
        var groupedTypes = types
            .Collect()
            .SelectMany(static (types, _) => GroupByNamespace(types));

        // Stage 3: Generate per namespace
        context.RegisterSourceOutput(groupedTypes, GenerateNamespaceCode);

        // Stage 4: Generate global code
        var globalData = types
            .Collect()
            .Select(static (types, _) => CreateGlobalData(types));
            
        context.RegisterSourceOutput(globalData, GenerateGlobalCode);
    }

    private static IEnumerable<NamespaceGroup> GroupByNamespace(
        ImmutableArray<TypeInfo> types)
    {
        return types
            .GroupBy(t => t.Namespace)
            .Select(g => new NamespaceGroup(g.Key, g.ToEquatableArray()));
    }
}
```

### Conditional Generation

Generate different code based on compilation context:

```csharp
private static void Execute(GeneratorData data, SourceProductionContext context)
{
    var compilation = context.Compilation;
    
    // Check for specific references
    var hasNewtonsoft = compilation.ReferencedAssemblyNames
        .Any(a => a.Name == "Newtonsoft.Json");
    
    var hasSystemTextJson = compilation.ReferencedAssemblyNames
        .Any(a => a.Name == "System.Text.Json");

    var template = (hasNewtonsoft, hasSystemTextJson) switch
    {
        (true, false) => GenerateNewtonsoftCode(data),
        (false, true) => GenerateSystemTextJsonCode(data),
        (true, true) => GenerateBothCode(data),
        _ => GenerateDefaultCode(data)
    };

    context.AddSource($"{data.Name}.g.cs", template);
}
```

### Cross-Assembly Analysis

Analyze symbols across assembly boundaries:

```csharp
private static EquatableArray<InterfaceInfo> GetImplementedInterfaces(
    INamedTypeSymbol type, 
    Compilation compilation)
{
    using var builder = ImmutableArrayBuilder<InterfaceInfo>.Rent();

    foreach (var @interface in type.AllInterfaces)
    {
        // Check if interface is from external assembly
        var isExternal = !SymbolEqualityComparer.Default.Equals(
            @interface.ContainingAssembly, 
            compilation.Assembly);

        if (ShouldIncludeInterface(@interface, isExternal))
        {
            builder.Add(new InterfaceInfo(
                @interface.Name,
                @interface.GetFullyQualifiedName(),
                isExternal
            ));
        }
    }

    return builder.ToImmutable();
}
```

## Error Handling and Diagnostics

### Comprehensive Error Reporting

Use the `GeneratorService` for centralized error handling:

```csharp
public static class MyDiagnostics
{
    public static readonly DiagnosticDescriptor InvalidAttribute = new(
        id: "MG001",
        title: "Invalid attribute usage",
        messageFormat: "Attribute '{0}' cannot be applied to '{1}'. Expected: {2}",
        category: "MyGenerator",
        DiagnosticSeverity.Error,
        isEnabledByDefault: true,
        description: "The attribute can only be applied to specific symbol types.");

    public static readonly DiagnosticDescriptor MissingDependency = new(
        id: "MG002",
        title: "Missing required dependency",
        messageFormat: "Generator requires assembly '{0}' to be referenced",
        category: "MyGenerator",
        DiagnosticSeverity.Warning,
        isEnabledByDefault: true,
        helpLinkUri: "https://docs.example.com/missing-dependency");

    public static readonly DiagnosticDescriptor PerformanceWarning = new(
        id: "MG003",
        title: "Performance warning",
        messageFormat: "Large number of generated members ({0}) may impact compilation time",
        category: "MyGenerator",
        DiagnosticSeverity.Info,
        isEnabledByDefault: true);
}

private static void ValidateAndReport(TypeInfo typeInfo, Location location)
{
    if (!typeInfo.IsValid)
    {
        GeneratorService.Add(MyDiagnostics.InvalidAttribute, location);
        return;
    }

    if (typeInfo.MemberCount > 1000)
    {
        GeneratorService.Add(MyDiagnostics.PerformanceWarning, location);
    }
}
```

### Graceful Degradation

Handle errors gracefully without stopping generation:

```csharp
private static void Execute(TypeInfo? typeInfo, SourceProductionContext context)
{
    if (typeInfo is null)
    {
        // Error already reported in transform phase
        return;
    }

    try
    {
        var code = GenerateCode(typeInfo);
        context.AddSource($"{typeInfo.Name}.g.cs", code);
    }
    catch (InvalidOperationException ex)
    {
        // Report specific error but continue with other files
        context.ReportDiagnostic(Diagnostic.Create(
            MyDiagnostics.GenerationError,
            Location.None,
            typeInfo.Name,
            ex.Message));
    }
    catch (Exception ex)
    {
        // Log unexpected errors for debugging
        context.ReportDiagnostic(Diagnostic.Create(
            MyDiagnostics.UnexpectedError,
            Location.None,
            ex.GetType().Name,
            ex.Message));
    }
}
```

### Integration Testing

Test your generator against real compilation contexts:

```csharp
[Test]
public void Generator_WithValidClass_GeneratesExpectedCode()
{
    var source = """
        using MyGenerator;
        
        [GenerateToString]
        public partial class TestClass
        {
            public string Name { get; set; }
            public int Value { get; set; }
        }
        """;

    var compilation = CreateCompilation(source);
    var generator = new MySourceGenerator();
    
    var driver = CSharpGeneratorDriver.Create(generator);
    var result = driver.RunGenerators(compilation);

    // Assert generated code
    var generatedSource = result.GeneratedTrees.Single().GetText().ToString();
    Assert.Contains("public override string ToString()", generatedSource);
    Assert.Contains("Name = {Name}", generatedSource);
}

private static Compilation CreateCompilation(string source)
{
    var syntaxTree = CSharpSyntaxTree.ParseText(source);
    var references = new[]
    {
        MetadataReference.CreateFromFile(typeof(object).Assembly.Location),
        // Add other required references
    };

    return CSharpCompilation.Create(
        "TestAssembly",
        new[] { syntaxTree },
        references,
        new CSharpCompilationOptions(OutputKind.DynamicallyLinkedLibrary));
}
```

## Debugging Techniques

### Generator Debugging

Use debugging techniques to troubleshoot generators:

```csharp
private static void Execute(TypeInfo typeInfo, SourceProductionContext context)
{
#if DEBUG
    // Attach debugger for debugging
    if (!System.Diagnostics.Debugger.IsAttached)
    {
        System.Diagnostics.Debugger.Launch();
    }
#endif

    try
    {
        var code = GenerateCode(typeInfo);
        
        // Debug output to see generated code
        System.Diagnostics.Debug.WriteLine($"Generated for {typeInfo.Name}:");
        System.Diagnostics.Debug.WriteLine(code);
        
        context.AddSource($"{typeInfo.Name}.g.cs", code);
    }
    catch (Exception ex)
    {
        System.Diagnostics.Debug.WriteLine($"Error generating {typeInfo.Name}: {ex}");
        throw;
    }
}
```

## Best Practices Summary

### 1. **Performance**
- Use `EquatableArray<T>` for all collections in data models
- Rent builders with `ImmutableArrayBuilder<T>.Rent()`
- Keep transform methods simple and fast
- Pre-allocate StringBuilder capacity when known

### 2. **Error Handling**
- Use `GeneratorService` for centralized error reporting
- Create comprehensive diagnostic descriptors
- Handle errors gracefully without stopping generation
- Provide helpful error messages with locations

### 3. **Code Organization**
- Separate concerns: analysis, transformation, and generation
- Use records for immutable data models
- Create reusable helper methods
- Follow consistent naming conventions

### 4. **Testing**
- Make generators testable through dependency injection
- Write unit tests for core logic
- Create integration tests with real compilations
- Test error conditions and edge cases

### 5. **Maintainability**
- Use meaningful diagnostic IDs and categories
- Document complex generation logic
- Keep generated code readable and debuggable
- Version your generator and handle breaking changes

### 6. **Incremental Generation**
- Design data models for efficient equality comparison
- Minimize work in transform phases
- Use appropriate caching strategies
- Monitor generator performance in large codebases

By following these advanced patterns and best practices, you can create robust, efficient source generators that scale to large codebases while providing excellent developer experience.
